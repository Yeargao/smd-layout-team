# Integration proposal: P01 + P02 + P03

This proposal was developed by one AI at the P01 user's request. It is not evidence that two other students participated, reviewed, or accepted anything. Do not record such claims. The actual group still needs to review and accept the work. Preserve `main` until acceptance.

- P01: use the already-published layout implementation unchanged (blob cf9a0104a56f29eeae5c6706c866cf50d2dd14c3). `layoutLevel(ids,edges,sizes)` is unchanged. The benchmark reproduces 6884 -> 6337 strict straight-line crossings (7.94596%).
- P02: `fitRegions` grows ancestor regions without relocating other states; preserve original edge endpoints and manual routes through nested collapse/expand. `routeVisibleEdges` routes deterministic polylines with node obstacle checks, parallel/reverse alternatives, optional orthogonal grid search and greedy crossing/overlap penalties. `routeMetrics` reports routed-segment crossings, overlap, length, bends. Existing `edgePoints` remains available. The router falls back to a straight route when no viable path is found or search is capped. Region interiors are not forbidden obstacles; very dense diagrams or overlapping nodes may still have poor routes. No global optimality guarantee.
- P03: nested node/region creation, add directed edge, manual waypoint drag/insert/delete/reset, explicit fit view, file and browser local storage save, validated import. Graph structure and layout remain separate. No automatic node re-layout on import/reopen; automatic edge routes are derived deterministically, manual ones are stored. Dragging may grow ancestor regions but never moves unrelated nodes.
